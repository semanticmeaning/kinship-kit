# Изменения kinship-kit

Формат: версия (метка git `vX.Y.Z`), дата, что нового. **Схема данных** — нужно ли выполнить `kin migrate` в своих делах.
Обновление: `kin upgrade check` → `kin upgrade apply` → в каждом деле `kin migrate --dry-run`. Данные дел не затрагиваются.

Схема данных без изменений (v2).

- Исправлено: если человека открывали по ссылке (`#P-…`) раньше, чем загрузилось фото, в шапке панели оставался
  силуэт вместо портрета. Теперь шапка обновляется, когда фото приходит.

## [0.8.0] — 2026-11-10
Схема данных без изменений (v2). Пересоберите сайт: `kin site build`.

- **Новый дизайн сайта-схемы.** Перенесён из реального дела.
  - Панель с вкладками **Персона** (рассказ, жизнь по годам, семья, документы и фото), **Гипотезы** (открытые вопросы,
    подтверждённые факты, ход поиска: где не нашли, отброшенные версии, решения) и **Поиск** (линии поиска).
  - Рамки версий вместо пунктирных линий «одно лицо?», потенциальные «мать / отец», знаки развода и вдовства.
  - Версия для телефона, тёмная тема, шрифт Inter в папке сайта: страница больше не обращается к Google Fonts.
- **Рассказы о людях** — `stories/P-….md` в папке дела. В публичную версию — только по решению автора
  (`kin case set privacy.public_stories=allow --by «Имя»`, решение пишется в журнал).
- **Портреты** — `case.json` → `site.portraits`: источник-фото и рамка лица. В публичной версии — только
  при `scan_publication=allow`.
- **Рамки версий, порядок браков, сила связи** — `case.json` → `site.versions`. Рамка, где есть скрытый в публичной
  версии человек, в неё не попадает целиком.
- **Проверка раскладки — в headless Chrome/Chromium** (вместо node): линии под карточками, наложения, ошибки панели
  у каждого человека, лишние люди в режиме «Только подтверждённые». Выполняется только страница набора с данными дела.
- Корень дела показывается всегда: у нового дела без связей схема не пустая.
- Английская версия переведена полностью; тест следит, чтобы в ней не оставалось русских подписей.
- Не перенесено из дела: автоматический выбор имени по написанию в документах. В наборе имя на схеме — `preferred_label`
  («Фамилия Имя Отчество», правило навыка); пояснение после « — » на схеме не показывается.

## [0.7.0] — 2026-11-10
Схема данных без изменений (v2). После обновления — `kin audit` в своих делах: появились новые предупреждения.

- **Аудит: проверки согласованности** (предупреждения, по опыту ревью схемы реального дела):
  - отчество ребёнка не сходится с именем отца;
  - ребёнок родился раньше, чем родителю исполнилось 12, или позже смерти родителя;
  - супруги одного пола;
  - связь на источнике у кандидата;
  - `identity` на трёх и больше людей или мужчины с женщиной;
  - гипотеза родства при уже подтверждённой связи той же пары;
  - дата утверждения о рождении или смерти не сходится с карточкой;
  - в обосновании или следующем шаге упомянут слитый человек;
  - одинаковый текст утверждений.
- **Правило о семейном дереве.** Семейное дерево и рассказы родственников — независимое подтверждение только для сведений
  о живых и на одно поколение от них. `corroborated`, которое держится на семейных сведениях о более далёких предках,
  даёт предупреждение. Демо-дела приведены к правилу.
- **Шаблон задания `tree-review`** — ревью схемы рода по образам документов: порции по линиям, не больше 30 образов,
  только чтение, пять групп находок, перепроверка до правок.
- CI: действия GitHub на Node 24. В README — новый скриншот сайта.

## [0.6.0] — 2026-11-05
Схема данных без изменений (v2). Пересоберите сайт: `kin site build`.

- Карточка человека: разделы «Факты», «Связи», «Гипотезы» и «Опровергнуто и не найдено». Последний по умолчанию скрыт,

- Галерея документов: сохранённая копия страницы сайта не показывается, если у источника есть значок внешней ссылки.
  Без ссылки копия остаётся в галерее как текст.
- Навык: соперничающие версии закрываются в том же коммите, что и находка; в отчёте — строка «Закрыто гипотез: N».

## [0.5.2] — 2026-11-02
Схема данных без изменений (v2). Исправления по ревью безопасности; обновиться всем, особенно в Windows.

- **Безопасность:** проверка раскладки при `kin site build` выполняла в node скрипт страницы дела
  (`theme/index.html`) с правами пользователя — чужое дело со своей темой могло читать и менять файлы. Теперь
  в node выполняется только страница из набора; из дела берутся только данные `tree.json`.
- **Windows: блокировка дела.** Блокировку живого процесса снимали через 10 минут (долгий импорт мог потерять её
  и два процесса писали одновременно); параллельная запись могла зависнуть на 30 секунд и упасть (файл блокировки,
  открытый другим процессом, не удалялся). Теперь процесс проверяется через Windows API, удаление повторяется,
  процесс снимает только свою блокировку; блокировку другой машины или непроверяемого процесса `kin` не снимает никогда.
- **Windows: кодировка.** Вывод `git` и `node` читался в кодировке системы (cp1252/cp1251) и в Windows мог молча
  пропадать (проверка раскладки, сведения о remote в `doctor`, автор коммитов в `setup`, проверка обновлений).
  Демо-скрипты (`examples/demo/build_demo*.py`) и инструменты падали на первой русской строке в консоли Windows.
  Теперь везде UTF-8; тест не даёт снова читать вывод программ без явной кодировки.
- CI: все тесты прогоняются и в Windows (обязательная проверка); упавшие тесты видны аннотациями в PR.

## [0.5.1] — 2026-11-02
Схема данных без изменений (v2).

- Установка команды `kin` через `pipx install -e .` или `uv tool install -e .` в клоне (`pyproject.toml`). Только с `-e`:

- README: для кого набор и какую проблему решает.

## [0.5.0] — 2026-11-02
Схема данных без изменений (v2). По итогам внешнего ревью.

- **MCP: белый список команд.** Через инструмент `kin` доступны только команды внутри дела; `export`, `import`,
  `backup`, `restore`, `gedcom`, `site publish`, `hooks install`, `agents install`, `upgrade apply`, `init`, `setup`
  и службы — только в терминале. Ключи с путём вне дела (`--out`, `--to`, `--target`…) и другое дело через `--case`
  отклоняются. Файлы для `source add` — только из папки дела или папок `KIN_MCP_INBOX` (docs/MCP.md).
- Блокировка дела: блокировку живого процесса больше не снимают через 10 минут (долгий импорт не потеряет её),
  брошенную после сбоя — снимают сразу. Откат транзакции пишет файлы атомарно.
- Дело на нескольких машинах: `kin doctor` напоминает «пишет один клон за раз» и находит следы конфликта git в реестрах
  (docs/ARCHITECTURE.md, docs/EXPORT.md).
- Сайт: цвет линии из `case.json` проверяется (только `#hex`) и экранируется на странице.
- Разработка: ruff с конфигом и обязателен в CI; модули и тесты названы по смыслу (`cli_exchange`, `cli_services`,
  `tests/test_core.py`, `test_workflow.py`, `test_exchange.py`, `test_site.py`, `test_services.py`).

## [0.3.0] — 2026-11-02

- Скачиватели сканов из онлайн-архивов: общее ядро (`downloaders/core.js`) — панель, папка, журнал и докачка по sha256,

## [0.2.0] — 2026-11-02
**Схема данных: v1 → v2 — выполните `kin migrate` в делах, созданных версией 0.1.0** (резервная копия создаётся сама).

- Первый шаг `kin setup`: фамилия, название дела, автор коммитов — явно; личный стоп-лист.
- Процесс исследования: `kin next`, жизненный цикл задач и гипотез, история решений, защита от повторных поисков,
  согласие пользователя на платное и внешние сервисы, шаблоны заданий, запросы в архивы.
- Независимое ревью значимых выводов (привязано к решению, засчитывается по журналу), роли агентов для Claude Code и Codex.
- Обмен и сохранность: полный экспорт/импорт JSON без дублей, `kin backup` / `kin restore`, GEDCOM 5.5.1, поиск `kin find`.
- MCP-сервер для ИИ-клиентов без командной строки.
- Форма «сведения семьи» на приватном сайте (черновик → решение исследователя).
- Публикация: показ живых по решению автора (`privacy.public_living`), закрытие скрытого вместо остановки сборки
  (`privacy.on_leak=redact`), личная тема сайта дела, выкладка `kin site publish`, демо на GitHub Pages.
- Английский интерфейс, руководство и демо-дело.
- Версии и обновления: `kin --version`, `kin upgrade check|apply`, напоминание в `kin status`.

## [0.1.0] — 2026-11-01
Схема данных v1.

- CLI `kin`: дело, источники с sha256, упоминания, личности, утверждения, связи, места, аудит доказательности, `kin status`.
- Сайт-схема рода: колена, гипотезы, профиль с источниками; публичная сборка без живых с проверкой утечек.
- Навык `kinship-kit` (на основе ex-ussr-kinship-research), синтетическое демо-дело, тесты, проверка приватности репозитория.
