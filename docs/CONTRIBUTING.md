# Улучшения из своего исследования → в общий набор

Данные семьи живут в деле (приватно). Улучшения инструмента — в этом репозитории, **в обобщённом виде**.

| Что нашли или придумали | Куда |
|---|---|
| Архив, база, приём поиска | `skills/kinship-kit/references/` |
| Правило работы | `skills/kinship-kit/SKILL.md`, `roles/`, `templates/tasks/` |
| Вид сайта | `skills/kinship-kit/kin/web/index.html` (у себя сначала — `kin site theme init [--full]`, затем `kin site theme diff`) |
| Ошибка или возможность кода | `skills/kinship-kit/kin/` + тест в `tests/` |

## Настройка один раз

```bash
git clone git@github.com:<вы>/kinship-kit.git ~/kinship-kit     # или свой форк
sh ~/kinship-kit/install.sh --link        # навык = ссылка на клон: агент сразу работает с вашими правками
git -C ~/kinship-kit config core.hooksPath .githooks             # проверка перед каждым коммитом
mkdir -p ~/.config/kinship-kit && nano ~/.config/kinship-kit/denylist.txt
```
`denylist.txt` — по строке: фамилии своей семьи, названия деревень, свой домен, адрес сервера. Файл лежит **вне**
репозитория; проверка `tools/check_repo.py` (хук и CI) не даст этим словам попасть в публичный код.

В инструкции агента своего дела (CLAUDE.md / AGENTS.md дела) полезно добавить:
> Улучшения инструмента (не данные семьи) — отдельной правкой в клоне kinship-kit, обобщённо, без имён, мест и шифров
> этой семьи; затем `sh tools/check.sh`, коммит, `git push`.

## Порядок правки

1. Правка в клоне набора (не в папке дела).
2. `sh tools/check.sh` — тесты и проверка приватности.
3. Существенное (модель данных, доказательность, экспорт, приватность) — независимое ревью (`docs/DEVELOPMENT.md`).
4. Коммит, `git push`. CI на GitHub повторит проверки и обновит демо-сайт.

Свой форк чужого набора: изменения — через Pull Request в исходный репозиторий.
