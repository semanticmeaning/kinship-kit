# GEDCOM 5.5.1: что переносится и что нет

## Экспорт — `kin gedcom export --out file.ged [--profile private|public] [--include-hypotheses]`

| kinship-kit | GEDCOM |
|---|---|
| Человек | `INDI`: `NAME Имя Отчество /Фамилия/`, девичья фамилия из скобок — второй `NAME` (`TYPE maiden`), варианты — `NAME` (`TYPE aka`), `SEX`, `REFN P-…` (`TYPE kinship-kit`), статус — `NOTE` |
| Утверждения birth/baptism/death/burial/residence/occupation | `BIRT/CHR/DEAT/BURI/RESI/OCCU`; прочие — `EVEN` с `TYPE`. **Каждая конкурирующая версия — отдельное событие**; статус и ID утверждения — в `NOTE` |
| Даты EDTF | `1885-03-02` → `2 MAR 1885`; `1855~` → `ABT 1855`; `1882?` → `EST 1882`; `1890/1905` → `BET 1890 AND 1905`; `../1917` → `BEF 1917`; `1900/..` → `AFT 1900` |
| Связи spouse-of / parent-of | `FAM` (`HUSB`/`WIFE`/`CHIL`), брак и развод — `MARR`/`DIV` |
| Источники | `SOUR` (`TITL`, `PUBL` = архив, `REFN A-…`), ссылки — `SOUR @…@` + `PAGE` (шифр) |

По умолчанию выгружаются только утверждения и связи с источниками; гипотезы — с `--include-hypotheses`.
Профиль `public` применяет фильтр публикации: живые и «возможно живые» не выгружаются, у семейных источников нет владельца
и ссылки; файл проверяется на утечки так же, как сайт.

## Импорт — `kin gedcom import file.ged [--group …] [--dry-run]`

- Файл регистрируется как источник: семейное древо, производный, группа независимости `family-tree:<имя файла>`.
  **Все сведения древа — одна группа**: они не подтверждают друг друга.
- Каждый `INDI` — упоминание этого источника (`GEDCOM @I12@`). Новые люди — статус `tree-entry-unverified`,
  `living_status` — `deceased` при наличии `DEAT`, иначе `unknown` (скрыты из публичной сборки).
- События → утверждения `single-source` с уверенностью `low` («наводка, нужна проверка по документам»);
  разные даты одного события в древе связываются как конкурирующие. `FAM` → связи `single-source`.

**Без размножения дублей:**
- тот же файл (sha256) повторно не импортируется;
- новая версия того же древа (та же группа): люди сопоставляются по `xref` прежнего импорта (и совпадению имени),
  уже имеющиеся события и связи не повторяются; добавляется только новое;
- экспорт этого же дела (метка `_KIN_CASE`) обратно не импортируется (`--allow-self` — осознанно);
- однофамильцы с уже существующими людьми **не сливаются**: импорт выводит список «возможные дубликаты» для проверки;
- другая дата того же события из новой версии древа сохраняется как конкурирующая версия;
- импорт атомарный: при любой ошибке реестры, журнал и скопированный файл откатываются — повтор возможен.

## Ограничения

Не переносятся: медиа (`OBJE`), адреса и контакты, `ASSO`, `ALIA`, источники-цитаты с текстом, качество (`QUAY`),
события кроме перечисленных (остальные при импорте пропускаются), упоминания, гипотезы, задачи, журнал поиска, ревью,
группы независимости, исторические места (`places`). Календарь: даты в `@#DJULIAN@` сохраняются числами с пометкой
«ст. ст.» в тексте утверждения; другие календари — только в тексте. Для полного переноса — `kin export` (docs/EXPORT.md).
