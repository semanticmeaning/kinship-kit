# Полный экспорт, резервная копия, восстановление

## Формат `kinship-kit-export` (JSON, версия 1)

```json
{
  "format": "kinship-kit-export", "format_version": 1, "schema_version": 2,
  "kin_version": "0.1.0", "exported_at": "2026-11-01T22:00:00+01:00",
  "case": { … case.json целиком … },
  "registers": { "persons": [ {строка с полями схемы}, … ], "claims": [ … ], … все 11 реестров },
  "journal": [ {"ts": …, "actor": …, "op": …, "id": …, "data": {…}}, … ],
  "sources": [ {"artifact_id": "A-0001", "file": "sources/A-0001__scan.jpg", "sha256": "…", "size": 12345,
                "content_base64": "…" } ]
}
```
- Строки реестров — ровно поля схемы (`kin schema`), значения — строки; списки ID через `;`.
- Журнал переносится целиком: на нём держится засчитывание ревью и история решений.
- `content_base64` — только с `--with-files`; без него переносится манифест, а файлы — резервной копией.
- Экспорт приватный (в нём живые, заметки, настройки владельца). Для публики — `kin site build --profile public`.

## Импорт без дублей

`kin import file.json [--dry-run]`:
- запись с тем же ID и тем же содержимым — пропуск; с тем же ID и другим содержимым — **конфликт, ничего не пишется**;
- новые записи проверяются по схеме и ссылкам вместе; файлы — по sha256;
- записи журнала добавляются, только если их ещё нет;
- в пустое дело импорт переносит и известные настройки (`case.json`) — это восстановление;
- повреждённый экспорт (повтор ID, не-строковые значения, испорченный журнал, путь источника вне `sources/`) отклоняется целиком.

Повторный импорт того же файла ничего не добавляет (проверено тестом). Экспорт другой версии схемы — сначала `kin migrate`.

## Резервная копия

`kin backup [--out файл.tar.gz] [--no-git]` — архив дела с `MANIFEST.json` (sha256 каждого файла), по умолчанию в
`~/kinship-backups/`. Включает реестры, источники, журнал, задания, запросы, черновики сведений семьи и историю git;
не включает производное (`site/`, `publish/`, индекс). Во время копирования дело заблокировано для записи.

`kin restore архив.tar.gz <новая папка>` — только в пустую папку; небезопасные элементы архива (абсолютные пути, `..`,
ссылки, устройства) отклоняются; после распаковки сверяются все контрольные суммы в обе стороны (файл из манифеста
изменён или отсутствует, либо в архиве есть файл вне манифеста — отказ), затем выполняется аудит. Существующие файлы
экспорта и резервных копий не перезаписываются (`--force` — только для `export` и `gedcom export`).

Перенос на другой компьютер: `kin backup` → скопировать архив → `kin restore`; или `git clone` приватного репозитория дела.
