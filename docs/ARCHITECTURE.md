# Архитектура хранения данных kinship-kit

Статус: этап 2. Схема данных v2. Решения — в `docs/adr/`.

## 1. Два хранилища, никогда не в одной папке

| | Набор `kinship-kit` (этот репозиторий) | Дело (папка исследования) |
|---|---|---|
| Что | Код CLI, навык, справочники, шаблон сайта, синтетический пример | Данные одной семьи |
| Доступ | Публичный | Приватный |
| Git | Публичный репозиторий | Свой git-репозиторий (локально или приватный remote) — по выбору пользователя |
| Защита | `tools/check_repo.py` (pre-commit и CI): нет `case.json`, реестров, `sources/`, e-mail, телефонов, личных путей, секретов, терминов из личного стоп-листа | `kin init` отказывается создавать дело внутри набора; `kin doctor` проверяет размещение и предупреждает о внешнем remote |

На `.gitignore` не полагаемся: проверяется **содержимое** файлов, а не только имена.

## 2. Выбор хранилища (требование 17.1)

| Вопрос | Решение | Почему |
|---|---|---|
| Основной формат | **Текстовые реестры CSV** в `registry/`, схема — `kin/schema.json` | Читаются человеком и ИИ, диффы в git построчные, переживут любые программы; объём личного исследования — тысячи строк, не миллионы |
| Реляционная БД | **Не источник истины.** SQLite — только производный индекс для поиска (этап 2, `kin index`, пересобирается) | Две редактируемые копии фактов запрещены; БД-файл плохо версионируется и сливается |
| Структурированные файлы | `case.json` — настройки дела (корень, линии поиска, приватность, лимиты); `journal.jsonl` — журнал действий | Настройки и журнал — не факты исследования |
| Индексация и поиск | Этап 1: `kin list --where`, `kin show` (обратные ссылки). Этап 2: SQLite FTS | Для MVP достаточно линейного чтения CSV |
| Версионирование | git в папке дела (`kin init` делает `git init`); `journal.jsonl` фиксирует кто/что/когда; история выводов — `claims.supersedes` + статус `superseded` | Git даёт полную историю и перенос; журнал — атрибуцию агентов |
| Миграции схемы | `schema_version` в `case.json` и в схеме; при несовпадении `kin` отказывается работать и просит `kin migrate`. Снимки прежних схем — `kin/schemas/vN.json`; `kin migrate` проверяет заголовки, делает резервную копию `.kin/backup-vN-…`, переносит данные (переименования — явно), при ошибке откатывает | Данные не теряются молча: исчезающее поле без переименования останавливает миграцию |
| Бэкап и восстановление | git (`git clone` = полная копия); `kin backup/restore` — этап 3 | Оригиналы в `sources/` — обычные файлы, проверяемые по sha256 |
| Несколько агентов | Межпроцессная блокировка `.kin/write.lock` на каждую запись, атомарная замена файла, перечитывание реестра под блокировкой | Проверено тестом: 16 параллельных записей → 16 уникальных ID |
| Перенос между компьютерами | Папка дела самодостаточна: `git clone` / копирование + установленный навык | Сервер и локальная машина — одинаковая структура |

## 3. Три слоя (требование 17.2)

```
дело/
├── case.json              настройки дела
├── sources/               RAW SOURCES — неизменяемые оригиналы (A-NNNN__имя), только чтение, sha256 в реестре
├── registry/              RESEARCH KNOWLEDGE BASE — единственный источник истины
│   ├── artifacts.csv      A-  источники: происхождение, шифр, группа независимости, sha256
│   ├── mentions.csv       M-  человек, как записан в источнике (имя, роль, возраст — дословно)
│   ├── persons.csv        P-  установленные личности (исследовательская сущность)
│   ├── claims.csv         C-  утверждения с источниками «за» и «против», статусом, конкурирующими версиями
│   ├── relationships.csv  R-  связи, подтверждённые утверждениями/источниками
│   ├── places.csv         L-  места и их принадлежность по периодам
│   ├── hypotheses.csv     H-  гипотезы
│   ├── tasks.csv          T-  исследовательские задачи (ResearchTask): ценность, стоимость, доступ, согласие
│   ├── searches.csv       S-  журнал поиска, включая отрицательные результаты и основания повтора
│   ├── reviews.csv        V-  независимые ревью (исполнители, проверяющий, прочитанные источники, решение человека)
│   └── requests.csv       Q-  запросы в архивы (канал, номер, сроки, ответ)
├── tasks/                 задания исполнителям (kin task new), requests/ — тексты запросов
├── journal.jsonl          журнал действий (кто, что, когда, до/после)
├── publish/<профиль>/     PUBLICATION DATASET — производный, только разрешённое (не в git)
└── site/<профиль>/        сайт, собранный только из publish/ (не в git)
```

Сайт не читает реестры: `kin site build` → `publish.build()` (фильтр) → проверка утечек → `tree.json` → повторная проверка всей папки сборки.

## 4. Качество модели (требование 17.3)

| Требование | Как реализовано |
|---|---|
| Устойчивые ID | `A-/M-/P-/C-/R-/L-/H-/T-/S-NNNN`, выдаются `kin`, не меняются (`kin update` запрещает менять ID) |
| Документ ≠ извлечённая запись | `artifacts` (документ) → `mentions` (запись о человеке в нём) |
| Упоминание ≠ личность | `mentions.person_id` + `link_status` (possible/probable/confirmed/rejected) + `link_rationale` |
| Альтернативные имена | `persons.name_variants`, дословное написание — в `mentions.name_as_written` |
| Неполные и приблизительные даты | Подмножество EDTF: `1885`, `1885-03`, `1855~`, `1882?`, `1890/1905`, `../1917` (`kin/edtf.py`) |
| Неизвестные значения | Пустое поле = неизвестно; «точно не знаем» для жизни — `living_status=unknown` |
| Историческая география | `places.jurisdictions` по периодам; место в источнике — дословно в `place_as_written` |
| Конкурирующие утверждения | Отдельные `claims` + `competing_claim_ids`; аудит предупреждает о несвязанных расхождениях дат |
| Доказательства за и против | `artifact_ids` / `contradicting_artifact_ids` у утверждений, связей и гипотез |
| Объединение и разделение | `kin person merge` (нужно `identity` ≥ corroborated или `--force --reason`) → `status=duplicate`, `merged_into`; `kin person unmerge`. Записи не переписываются: ссылки на дубликат читаются через `resolve_person` |
| История выводов | `claims.supersedes` + статус `superseded`; `journal.jsonl` хранит «до/после» каждого изменения; git |
| Происхождение утверждения | `claim → artifact_ids/mention_ids → artifact (provenance, repository, archival_reference, url, file, sha256)` |

Ссылки на исходные данные сохраняются после смены интерпретации: слияние не удаляет записи, `superseded` не удаляет утверждение.

## 5. Правила аудита (`kin audit`)

Ошибки (сборка сайта останавливается): нарушение схемы и словарей, битые ссылки, дубли ID, изменённый или
отсутствующий файл источника, `corroborated` без двух независимых групп или без `rationale`, утверждение/связь
без источников вне статуса `hypothesis`, источник одновременно «за» и «против», слияние без обоснования, циклы,
гипотеза `rejected` без источников «против».

Предупреждения: нет группы независимости, несвязанные расхождения дат, `single-source` при нескольких группах,
`strongly-corroborated` без прямой записи, отрицательный поиск без «что нельзя выводить», закрытая задача без причины.

## 6. Публикация (требования 17.2, 22)

Профиль `private`: всё, кроме `publication=deny` и дубликатов. Профиль `public`: дополнительно скрыты живые,
лица с неизвестным статусом без даты смерти и с рождением позже чем `living_cutoff_years` (100) лет назад,
отвергнутые/заменённые утверждения, гипотезы, группы независимости; никогда не выгружаются `notes`, `provenance`,
пути к файлам, sha256. Проверка утечек ищет имена скрытых людей в любом падеже (пары «Имя Отчество»,
«Фамилия Имя»), их ID, e-mail, телефоны, локальные пути — при находке сборка удаляется и команда завершается ошибкой.

## 7. Ограничения (честно)

- GEDCOM, собственный формат полного экспорта, `kin backup/restore`, SQLite-индекс — не реализованы (этап 3).
- Журнал (`journal.jsonl`) — основа проверки «исполнитель ≠ проверяющий», засчитывания ревью и истории решений.
  Команды `kin` не позволяют менять ревью в обход, аудит сверяет `reviews.csv` с журналом, но сам журнал можно
  отредактировать вручную: подлинность обеспечивает git-история дела. Роли (`--as`) не аутентифицируются.
- Защита от повторного поиска сравнивает слова и номера источника, запрос, период и людей; транслитерацию и синонимы
  («ГАОО» / «Государственный архив …») не распознаёт.
- Аудит проверяет оформление доказательств, а не их историческую истинность. Источник без `independence_group`
  в кроссподтверждение не засчитывается (группу задаёт исследователь, `kin` её не угадывает).
- Проверка утечек — эвристика. Ловит любые две части ФИО скрытого человека (включая девичью фамилию и варианты)
  в любом падеже и порядке, с «ё/е», ID, e-mail, типичные телефоны и локальные пути. **Не ловит** одиночное имя
  или фамилию («внук Иван», «жена Петрова»), опечатки и инициалы — для публичной выкладки нужен просмотр человеком.
- В публичной сборке у семейных источников (`family-oral`, `family-tree`, `letter`, `photo`) не выводятся владелец
  и ссылка; у остальных ссылка выводится, только если это `http(s)`. Заголовок источника выводится всегда — не пишите в него имён живых.
- CSV не защищены от «формул» при открытии в табличном редакторе (значения, начинающиеся с `=`, `+`, `-`, `@`):
  открывайте реестры через импорт с текстовыми столбцами. Экранирование исказило бы данные.
- Блокировка — файловая, рассчитана на одну машину (не на сетевые ФС с несколькими хостами).
