# Правила независимого ревью

Цель — чтобы значимый вывод проверял не тот, кто его сделал, и проверял по первичным источникам, а не по резюме.
Автоматическая проверка не гарантирует истину: для живых людей, спорных выводов и публикации остаётся решение человека.

## Что требует ревью

Политика дела — `case.json` → `review.required_for` (по умолчанию):

| Решение | Ключ |
|---|---|
| Гипотеза принята | `hypothesis:accepted` |
| Гипотеза опровергнута | `hypothesis:rejected` (дополнительно нужны источники «против») |
| Утверждение «надёжно подтверждено» | `claim:strongly-corroborated` |
| Слияние двух людей в одного | `merge` (ревью identity-утверждения) |

Пока ревью не пройдено, `kin` отказывает в этих действиях, а `kin audit` считает их ошибкой.
Изменение записи или связанных с ней утверждений и источников **после** ревью снимает его силу — нужно новое ревью.
Само решение по статусу (`kin hypothesis status …`, `status=strongly-corroborated`) изменением не считается.
Слияние вопреки правилу (`kin person merge … --force`) — только решение человека: `--by «Имя» --reason «…»`.

## Порядок

1. Исполнитель: `kin review request <ID> --for accepted|rejected|strongly-corroborated|merge` — ревью привязано к
   **конкретному решению**; фиксируются исполнители записи (из журнала) и замечания чек-листа, оценённые так,
   будто решение уже принято. Ревью без `--for` — общее, оно не разрешает ни одного из решений выше.
2. Проверяющая роль (по умолчанию Evidence Reviewer, `--as "Evidence Reviewer"`):
   - `kin review checklist <ID>` — `block` (пройти нельзя), `warn` (разобрать), `human` (нужно решение человека);
   - читает первичные источники (`sources/`, `kin show A-…`);
   - `kin review submit V-… --verdict passed|failed|needs-work --findings "…" --checked A-…;A-…`.
3. Если отмечено «нужно решение человека» — `kin review decide V-… --by «Имя» [--reject] [--note …]`.

## Что проверяет `kin`

- Засчитывается запись `review` в журнале дела, а не строка `reviews.csv`; строку нельзя изменить командой `kin update`/`kin add`,
  а расхождение строки с журналом (ручная правка CSV) — ошибка аудита.
- Перед самим решением чек-лист перепроверяется: появившееся блокирующее замечание отменяет разрешение.

- Проверяющий не совпадает ни с одним исполнителем записи (по журналу), и это не безымянный `user`.
- `--checked` обязателен, если у вывода есть источники, и содержит только источники этого вывода.
- `passed` невозможен при блокирующих замечаниях чек-листа (нет источников «за», статус выше обоснования,
  «против» без объяснения, все проверяемые утверждения — гипотезы, нерешённые противоречия, все задачи закрыты без находок…).
- `failed` и `needs-work` требуют описания недостатков.
- Касается живых или возможно живых людей → `human_required=yes`, без решения человека ревью не засчитывается.

## Чего `kin` проверить не может

Что ревьюер действительно прочитал источники и мыслит независимо. Поэтому роль Evidence Reviewer по умолчанию
скептична, а для чувствительных случаев решение остаётся за человеком.
